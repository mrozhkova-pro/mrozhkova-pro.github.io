# M.Rozhkova.Pro | Методист-разработчик

Двухстраничный сайт-визитка Марины Рожковой, методиста-разработчика образовательных программ. Создаёт образовательные программы, которые приносят результат: методические комплексы под ключ — от концепции до готового УМК. Для образовательных организаций, учебных центров ДПО и компаний с корпоративным обучением.

## Стек

- Статический сайт на чистом HTML5 — две страницы: `index.html` (главная) и `portfolio.html` (портфолио).
- CSS — встроенный в страницы (адаптивная вёрстка, анимации, 3D-кнопки, стеклянная шапка с размытием).
- JavaScript — встроенные скрипты (canvas-анимация в hero-секции, наблюдатель появления блоков, просмотр PDF на главной странице и в портфолио).
- PDF.js 3.11.174 (legacy-сборка) — лежит локально в папке `pdfjs/`, без CDN и внешних запросов.
- Без фреймворков, без сборщиков, без внешних шрифтов.

## Портфолио

На странице `portfolio.html` размещены 9 работ в следующем порядке:

1. Программы ДПО
2. Программы ПО
3. Методическое сопровождение разработки программы обучения с привлечением экспертов
4. Пример лекции
5. Пример учебного материала
6. Пример Учебные материалы
7. Практические задания
8. Пример учебных материалов по Охране труда
9. Презентация

Для каждой работы в папке `Портфолио/` хранятся PDF и превью первой страницы `.prev.png` шириной 2100 px. Исходные документы Word после конвертации в PDF в репозитории не хранятся.

PDF открываются во встроенном просмотрщике. Возможности:

- вертикальная прокрутка всех страниц подряд — без листания вбок;
- страница по умолчанию целиком помещается в окно: и на компьютере, и на телефоне;
- счётчик текущей страницы и кнопки ‹ › для перехода к предыдущей/следующей;
- зум 1×–3× и возврат к режиму «Целиком»;
- резервная ссылка «Открыть PDF в новой вкладке», если документ не удалось показать.

На компьютере при открытии страницы с диска (`file://`) автоматически используется встроенный просмотрщик браузера: PDF.js не может читать локальные файлы из-за CORS. На телефонах PDF.js работает при открытии сайта по HTTP(S).

## Презентация на главной

На `index.html` в hero-секции рядом с бейджем «Методист-разработчик» есть кнопка **«Презентация»**. Она оформлена в том же золотом 3D-стиле, что и кнопка «Связаться» в шапке: тот же градиент, объём, блик и пульсация при наведении. В обычном состоянии надпись тёмно-бирюзовая (`#004D54`), при наведении становится белой; цвет меняется плавно за 0,3 с. Высота кнопки совпадает с бейджем, на узких экранах размеры уменьшаются.

По нажатию открывается файл `M.Rozhkova_Pro_Presentation.pdf` в том же встроенном просмотрщике на PDF.js, что и работы в портфолио:

- вертикальная прокрутка всех 13 страниц;
- счётчик страниц и кнопки ‹ › для перехода;
- зум 1×–3× и возврат к режиму «Целиком»;
- закрытие по крестику, клику по фону и клавише Esc;
- блокировка прокрутки страницы под окном и возврат фокуса на кнопку;
- резервная ссылка «Открыть PDF в новой вкладке», если документ не удалось показать.

Просмотрщик подключает `pdfjs/pdf.min.js` и `pdfjs/pdf.worker.min.js` локально, без CDN. На компьютере при открытии страницы с диска (`file://`) PDF.js не может прочитать файл из-за CORS, поэтому автоматически используется встроенный просмотрщик браузера (iframe). Для проверки именно PDF.js открывайте сайт через локальный HTTP-сервер.

### Как обновить презентацию на сайте

1. Экспортировать актуальный PPTX в PDF с тем же именем `M.Rozhkova_Pro_Presentation.pdf`.
2. Проверить, что в PDF 13 страниц и он открывается без ошибок.
3. Положить файл в корень проекта вместо прежнего.
4. Закоммитить и запушить в `main` — workflow `deploy.yml` уже копирует PDF в публичный репозиторий, править `index.html` не нужно.
5. После публикации открыть сайт, нажать «Презентация» и проверить загрузку страниц, переходы и зум.

## Схема деплоя

`push` в `main` репозитория `mrozhkova-pro/my-site` → GitHub Actions (`deploy.yml`) копирует в публичный репозиторий `mrozhkova-pro/mrozhkova-pro.github.io`:

- страницы `index.html`, `portfolio.html` и `README.md`;
- картинки `hero-bg.jpg`, `qr-mail.png`, `qr-max.png`;
- PDF презентации `M.Rozhkova_Pro_Presentation.pdf`;
- папку `pdfjs/` с локальной сборкой PDF.js;
- папку `Портфолио/` с примерами работ.

→ GitHub Pages публикует сайт.

## Как обновлять

1. Внести правки в `index.html` / `portfolio.html` (тексты, стили, контакты).
2. Закоммитить: `git add .; git commit -m "Описание изменений"`.
3. Запушить в `main`: `git push`.
4. GitHub Actions автоматически переопубликует сайт (обычно 1–2 минуты).

### Добавление или замена работы в портфолио

1. Конвертировать исходный DOCX в PDF и положить PDF в `Портфолио/`.
2. Подготовить превью первой страницы в PNG шириной 2100 px и сохранить как `<имя работы>.prev.png`.
3. Добавить или заменить карточку `<article class="pf-card">` в `portfolio.html`, проверив путь в `data-href` и `src` превью.
4. Удалить исходный DOCX, закоммитить изменения и запушить в `main`.

Деплой требует настроенного в приватном репозитории GitHub-секрета `PAGES_DEPLOY_TOKEN` с правами записи в публичный репозиторий.

## Локальная разработка

Сайт — статический, сборка не нужна:

- **Простой способ:** открыть `index.html` в браузере двойным кликом.
- **Через локальный сервер:** `python -m http.server` в корне папки, затем открыть `http://localhost:8000/`.

При открытии через `file://` на компьютере PDF показываются встроенным просмотрщиком браузера (PDF.js не может читать локальные файлы из-за CORS). Для проверки мобильного просмотрщика и для телефонов запускайте локальный сервер.

### Быстрая проверка после правок

1. Открыть главную на ширине 1440–1416 px: бейдж и кнопка «Презентация» стоят в один ряд, без наложений.
2. Проверить 390, 360 и 320 px: нет горизонтального скролла, кнопка и бейдж не разъезжаются.
3. Навести мышь на «Презентацию»: надпись должна стать белой, как у «Связаться»; после ухода курсора — снова тёмно-бирюзовой.
4. Нажать кнопку: PDF открывается, видно 13 страниц, работают ‹ ›, зум и «Целиком», окно закрывается по Esc.
5. Посмотреть консоль браузера: ошибок быть не должно.
6. При проверке с диска (`file://`) убедиться, что сработал резервный просмотрщик браузера.

Локальный журнал `chat-history.txt` ведётся для истории работ по сайту и на сайт не публикуется.
